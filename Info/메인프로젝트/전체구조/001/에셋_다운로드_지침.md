## 2. AI에게 전달할 작업 지시

> 이 문서의 두 저장소를 다운로드해 주세요. Windows에서는 PowerShell을 사용하고 다운로드 위치는 아래 예시 또는 사용자가 지정한 경로를 적용하세요. 기존 폴더와 파일을 삭제하거나 덮어쓰지 마세요. Git 사용 가능 여부를 먼저 확인하고, 각 명령의 종료 코드를 확인하세요. Unity Robotics Hub는 서브모듈을 포함하여 다운로드하세요. 다운로드 후 Niryo One의 URDF·메시·Unity 예제와 컨베이어벨트의 Prefab·Scene·Script를 실제 파일 기준으로 확인하세요. 저장소 주소, 저장 경로, 커밋 SHA, 확인된 모델 경로, 누락 파일 및 오류를 보고하세요. 다운로드 실패 또는 파일 누락을 성공으로 보고하지 마세요. 이번 작업에서 기존 Unity 프로젝트로 에셋을 자동 복사하거나 씬을 수정하지 마세요.

## 3. Windows PowerShell 다운로드 명령

아래 경로는 예시이다. AI는 사용자가 지정한 다운로드 위치가 있으면 그 위치를 사용한다. 프로젝트의 `Assets` 내부가 아닌 별도 다운로드 폴더에 원본 저장소를 받는다.

```powershell
# 1) Git 사용 가능 여부 확인
git --version
if ($LASTEXITCODE -ne 0) { throw 'Git을 사용할 수 없습니다. Git 설치 또는 PATH 설정이 필요합니다.' }

# 2) 다운로드 위치 설정
$downloadRoot = Join-Path ([Environment]::GetFolderPath('Desktop')) 'FactorySimulationDownloads'
New-Item -ItemType Directory -Path $downloadRoot -Force | Out-Null

# 3) 기존 경로 보호: 두 대상 중 하나라도 있으면 먼저 내용을 확인
$robotRepo = Join-Path $downloadRoot 'Unity-Robotics-Hub'
$conveyorRepo = Join-Path $downloadRoot 'Conveyor-Belt-System-Simulation-in-Unity'
if ((Test-Path -LiteralPath $robotRepo) -or (Test-Path -LiteralPath $conveyorRepo)) {
    throw '대상 폴더가 이미 있습니다. 기존 저장소 확인 또는 새 다운로드 경로 선택 후 진행하세요.'
}

# 4) Niryo One 공식 예제: 서브모듈 포함 다운로드
git clone --recurse-submodules https://github.com/Unity-Technologies/Unity-Robotics-Hub.git $robotRepo
if ($LASTEXITCODE -ne 0) { throw 'Unity Robotics Hub 다운로드 실패' }

# 5) 컨베이어벨트 프로젝트 다운로드
git clone https://github.com/MuhammadNafishGinanjar/Conveyor-Belt-System-Simulation-in-Unity.git $conveyorRepo
if ($LASTEXITCODE -ne 0) { throw '컨베이어벨트 프로젝트 다운로드 실패' }

# 6) 실제 다운로드 버전 기록
git -C $robotRepo rev-parse HEAD
if ($LASTEXITCODE -ne 0) { throw '로봇팔 저장소 커밋 확인 실패' }
git -C $conveyorRepo rev-parse HEAD
if ($LASTEXITCODE -ne 0) { throw '컨베이어 저장소 커밋 확인 실패' }
git -C $robotRepo submodule status --recursive
if ($LASTEXITCODE -ne 0) { throw '서브모듈 상태 확인 실패' }
```

AI는 이미 존재하는 폴더에서 강제 재다운로드를 하지 않는다. 기존 폴더가 정상 Git 저장소이면 `git remote -v`, `git status --short`, `git rev-parse HEAD`로 원본과 변경 사항을 먼저 확인한다. 이번 다운로드 요청만으로 기존 작업 내용을 초기화하거나 임의 업데이트하지 않는다.

## 4. 다운로드 후 파일 검증

### 4.1 Niryo One

공식 Pick-and-Place 설명에서 안내하는 위치는 다음과 같다. 실제 다운로드 결과와 비교하고, 경로가 달라졌다면 파일 검색으로 실제 위치를 확인한다.

| 항목 | 저장소 내부 예상 경로 |
| --- | --- |
| Unity 예제 프로젝트 | `tutorials/pick_and_place/PickAndPlaceProject` |
| Unity용 URDF | `tutorials/pick_and_place/PickAndPlaceProject/Assets/URDF/niryo_one/niryo_one.urdf` |
| 모델·URDF 패키지 | `tutorials/pick_and_place/ROS/src/niryo_one_urdf` |
| 가져오기·관절 제어 설명 | `tutorials/pick_and_place/1_urdf.md` |

```powershell
# 앞 단계의 $robotRepo 변수를 이어서 사용
Get-ChildItem -LiteralPath $robotRepo -Recurse -File -Filter '*niryo*'
Get-ChildItem -LiteralPath $robotRepo -Recurse -File |
    Where-Object { $_.Extension -in '.urdf', '.xacro', '.dae', '.stl' } |
    Select-Object FullName, Length

$niryoUrdf = Join-Path $robotRepo 'tutorials/pick_and_place/PickAndPlaceProject/Assets/URDF/niryo_one/niryo_one.urdf'
if (Test-Path -LiteralPath $niryoUrdf) {
    Select-String -LiteralPath $niryoUrdf -Pattern '<joint', '<link', '<mesh'
} else {
    Write-Warning '안내된 Niryo URDF 경로가 없습니다. 실제 파일 검색 결과를 확인하세요.'
}
```

검증 기준:

- Niryo One URDF에 `joint` 및 `link` 정의가 있는지 확인한다.
- URDF에서 참조하는 메시 파일이 실제로 존재하는지 확인한다. URDF 하나만 다운로드한 상태는 모델 확보 완료로 처리하지 않는다.
- Unity 예제 프로젝트의 `Assets`, `Packages`, `ProjectSettings`를 확인한다.
- 메시 파일이 0바이트이거나 Git LFS 포인터 텍스트만 있는 경우 실제 모델 확보 완료로 보고하지 않는다.
- 서브모듈 상태에서 앞에 `-`가 나타나면 초기화되지 않은 상태이다. `+`는 상위 저장소가 지정한 커밋과 다른 상태, `U`는 충돌 상태이므로 결과에 기록한다.

### 4.2 컨베이어벨트

제작자 README에서 안내하는 위치는 다음과 같다.

| 항목 | 저장소 내부 예상 경로 |
| --- | --- |
| 컨베이어 및 생성 오브젝트 Prefab | `Assets/Prefabs` |
| 기본 실행 씬 | `Assets/Scenes/Conveyor_Arduino.unity` |
| 제어·생성 스크립트 | `Assets/Scripts` |
| 사용된 공장 모델 에셋 | `Assets/EKstudio` |

```powershell
# 앞 단계의 $conveyorRepo 변수를 이어서 사용
$conveyorAssets = Join-Path $conveyorRepo 'Assets'
if (-not (Test-Path -LiteralPath $conveyorAssets)) { throw '컨베이어 Assets 폴더 누락' }

Get-ChildItem -LiteralPath $conveyorAssets -Recurse -File |
    Where-Object { $_.Extension -in '.prefab', '.unity', '.fbx', '.obj', '.dae', '.cs' } |
    Select-Object FullName, Length

$conveyorScene = Join-Path $conveyorRepo 'Assets/Scenes/Conveyor_Arduino.unity'
if (-not (Test-Path -LiteralPath $conveyorScene)) {
    Write-Warning '안내된 실행 씬이 없습니다. 실제 씬 파일 위치를 확인하세요.'
}
```

검증 기준:

- 컨베이어 Prefab과 해당 Prefab이 참조하는 메시·머티리얼이 포함되어 있는지 확인한다.
- 물체 생성, 속도 조절, 시작·정지 및 삭제 구역 관련 스크립트의 실제 위치를 확인한다.
- `.meta` 파일은 원본 에셋과 함께 유지한다. Unity 참조 관계를 보존하기 위해 임의 삭제하지 않는다.
- 이 저장소는 Asset Store의 `Low Poly Factory Machine Pack Demo`를 사용한다고 명시한다. 모델이 누락되었다면 누락 항목과 원본 에셋 링크를 README에서 확인하여 보고한다.

## 5. 서브모듈 및 Git LFS 대응

로봇팔 저장소의 서브모듈 다운로드가 중단됐고 해당 폴더가 이번 작업에서 만든 정상 저장소라면 다음 명령으로 초기화를 다시 시도한다.

```powershell
git -C $robotRepo submodule update --init --recursive
if ($LASTEXITCODE -ne 0) { throw '서브모듈 초기화 실패' }
```

각 저장소의 `.gitattributes`에 `filter=lfs`가 있거나 모델 파일 내용이 `version https://git-lfs.github.com/spec/v1`로 시작하면 Git LFS가 필요한 상태인지 확인한다. 필요한 경우에만, 해당 저장소에서 실행한다.

```powershell
git lfs version
# 위 명령이 성공한 경우, LFS가 필요한 저장소 경로를 지정
$lfsRepo = $robotRepo  # 컨베이어 저장소라면 $conveyorRepo로 변경
git -C $lfsRepo lfs install --local
if ($LASTEXITCODE -ne 0) { throw 'Git LFS 저장소 설정 실패' }
git -C $lfsRepo lfs pull
if ($LASTEXITCODE -ne 0) { throw 'Git LFS 파일 다운로드 실패' }
```

Git 또는 Git LFS가 없고 AI에게 설치 권한이 없다면 필요한 도구와 실패 내용을 보고한다. 모델이 필요한 상태에서 코드만 받은 결과를 성공으로 처리하지 않는다.

## 6. 다른 운영체제에서 다운로드

Linux/macOS에서는 사용자가 지정한 별도 다운로드 폴더에서 다음 명령을 실행한다. 각 명령이 성공했는지 확인한 다음 다음 단계로 진행한다.

```bash
git --version
mkdir -p FactorySimulationDownloads
cd FactorySimulationDownloads
git clone --recurse-submodules https://github.com/Unity-Technologies/Unity-Robotics-Hub.git
git clone https://github.com/MuhammadNafishGinanjar/Conveyor-Belt-System-Simulation-in-Unity.git
git -C Unity-Robotics-Hub rev-parse HEAD
git -C Unity-Robotics-Hub submodule status --recursive
git -C Conveyor-Belt-System-Simulation-in-Unity rev-parse HEAD
```

같은 이름의 기존 폴더가 있으면 먼저 확인하고, 삭제하거나 덮어쓰지 않는다. 파일 검증 기준은 Windows 절차와 동일하다.

## 7. Unity에서 사용하기 전 확인

- Niryo One 예제는 URDF Importer를 이용하며 관절별 제어 예제가 있다. 전체 큐브 집기·배치 튜토리얼은 ROS 연동 단계를 포함하므로 다운로드만으로 모든 동작이 준비되었다고 판단하지 않는다.
- Unity Robotics Hub의 현재 메인 README는 Simulation Pro 중심으로 변경되어 있다. 선택한 대상은 Niryo One Pick-and-Place 예제이므로 실제 `tutorials/pick_and_place` 파일을 확인한다. 파일이 없다면 모델을 다른 로봇으로 임의 교체하지 않고 변경 사실을 보고한다.
- 컨베이어 제작자 README의 요구 버전은 Unity 2021.3 LTS 이상이다. 실제 프로젝트 버전은 다운로드한 `ProjectSettings/ProjectVersion.txt`를 확인한다.
- 사용자의 Unity 버전에서 컴파일·임포트·Play Mode 검증을 하기 전에는 호환성이나 실행 성공을 단정하지 않는다.
- 각 저장소의 라이선스와 포함된 외부 에셋 조건을 구분해 확인한다. GitHub 공개 여부만으로 모델 재배포·상업 이용 허가를 단정하지 않는다.
